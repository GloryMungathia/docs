The farmer endpoints let administrators and cooperative agents manage farmer accounts — from onboarding through verification status updates. Because farmers interact with the platform via USSD using a 4-digit PIN, account management is performed on their behalf by agents or admins through this API. The user management section at the bottom of this page covers admin-only operations on all platform user records.

<Note>
  All farmer management endpoints require an **Admin or Cooperative Agent** Bearer token. The PIN change endpoint is restricted to the authenticated farmer only. The user management endpoints require an **Admin** Bearer token unless otherwise noted.
</Note>

---

## POST /farmers/onboard

Registers a new farmer on the platform and associates them with a cooperative. The farmer can list produce via USSD immediately after onboarding. The endpoint creates both a base user record and a linked farmer record in a single transaction.

**Authentication required:** Admin or Agent Bearer token

<ParamField body="user" type="object" required>
  The base user fields for the farmer account.

  <Expandable title="user fields">
    <ParamField body="first_name" type="string" required>
      Farmer's given name. 1–100 characters.
    </ParamField>
    <ParamField body="last_name" type="string" required>
      Farmer's family name. 1–100 characters.
    </ParamField>
    <ParamField body="phone_number" type="string" required>
      Farmer's mobile number. This is their primary credential for USSD authentication.
    </ParamField>
    <ParamField body="nrc_number" type="string" required>
      Zambian National Registration Card number. Required on all user records. Max 20 characters.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="farmer" type="object" required>
  The farmer-specific fields.

  <Expandable title="farmer fields">
    <ParamField body="cooperative_id" type="string" required>
      UUID of the cooperative this farmer belongs to.
    </ParamField>
    <ParamField body="pin" type="string" required>
      The farmer's initial 4-digit numerical PIN.
    </ParamField>
  </Expandable>
</ParamField>

<ResponseField name="farmer_id" type="string">
  UUID of the newly created farmer record.
</ResponseField>

<ResponseField name="user_id" type="string">
  UUID of the associated base user record.
</ResponseField>

<ResponseField name="cooperative_id" type="string">
  UUID of the cooperative the farmer is registered under.
</ResponseField>

<ResponseField name="is_verified" type="boolean">
  Verification status. Defaults to `false` on creation.
</ResponseField>

<ResponseField name="is_active" type="boolean">
  Account active status. Defaults to `true` on creation.
</ResponseField>

```bash
curl -X POST https://pamodzi-bbe9f0671866.herokuapp.com/farmers/onboard \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-admin-or-agent-token>" \
  -d '{
    "user": {
      "first_name": "Bwalya",
      "last_name": "Tembo",
      "phone_number": "+260977000100",
      "nrc_number": "234567/89/1"
    },
    "farmer": {
      "cooperative_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
      "pin": "5678"
    }
  }'
```

## GET /farmers/

Returns a list of all active (non-archived) farmer records on the platform. Each record includes the farmer's profile and cooperative association.

**Authentication required:** Admin or Agent Bearer token

<ResponseField name="farmer_id" type="string">

</ResponseField>

<ResponseField name="user_id" type="string">

</ResponseField>

<ResponseField name="cooperative_id" type="string">
  UUID of the cooperative the farmer belongs to.
</ResponseField>

<ResponseField name="is_verified" type="boolean">
  Whether the farmer has been verified by an agent or admin.
</ResponseField>

<ResponseField name="is_active" type="boolean">

</ResponseField>

```bash
curl -X GET https://pamodzi-bbe9f0671866.herokuapp.com/farmers/ \
  -H "Authorization: Bearer <your-admin-or-agent-token>"
```

## PUT /farmers/{farmer_id}/verification

Updates the verification status of a farmer account. Verifying a farmer confirms their identity and eligibility to have produce listings accepted into campaign pools.

**Authentication required:** Admin or Agent Bearer token

<ParamField path="farmer_id" type="string" required>
  UUID of the farmer whose verification status you want to update.
</ParamField>

<ParamField body="is_verified" type="boolean" required>
  Set to `true` to mark the farmer as verified, or `false` to unverify them.
</ParamField>

<ResponseField name="farmer_id" type="string">
  UUID of the updated farmer record.
</ResponseField>

<ResponseField name="is_verified" type="boolean">
  The updated verification status.
</ResponseField>

<ResponseField name="user_id" type="string">
  UUID of the linked base user record.
</ResponseField>

<ResponseField name="cooperative_id" type="string">
  UUID of the cooperative the farmer belongs to.
</ResponseField>

```bash
curl -X PUT https://pamodzi-bbe9f0671866.herokuapp.com/farmers/a1b2c3d4-e5f6-7890-abcd-ef1234567890/verification \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-admin-or-agent-token>" \
  -d '{
    "is_verified": true
  }'
```

## DELETE /farmers/{farmer_id}

Archives (soft-deletes) a farmer account. The record is retained but the farmer can no longer log in or submit produce listings.

**Authentication required:** Admin or Agent Bearer token

<ParamField path="farmer_id" type="string" required>
  UUID of the farmer account to archive.
</ParamField>

<ResponseField name="message" type="string">
  A confirmation message, e.g. `"Farmer archived successfully."`.
</ResponseField>

<ResponseField name="farmer_id" type="string">
  UUID of the archived farmer record.
</ResponseField>

<Warning>
  Archiving a farmer account takes effect immediately — the farmer loses access to the platform. Confirm the intent before calling this endpoint.
</Warning>

```bash
curl -X DELETE https://pamodzi-bbe9f0671866.herokuapp.com/farmers/a1b2c3d4-e5f6-7890-abcd-ef1234567890 \
  -H "Authorization: Bearer <your-admin-or-agent-token>"
```

## POST /farmers/me/change-pin

Allows the authenticated farmer to rotate their own 4-digit security PIN. The farmer must supply their current PIN to authorise the change. Agents and admins cannot use this endpoint to change another farmer's PIN.

**Authentication required:** Farmer Bearer token (self only)

<ParamField body="current_pin" type="string" required>
  The farmer's existing 4-digit PIN. Used to verify intent before the change is applied.
</ParamField>

<ParamField body="new_pin" type="string" required>
  The new 4-digit numerical PIN. Must differ from the current PIN.
</ParamField>

<ResponseField name="message" type="string">
  A confirmation message, e.g. `"PIN updated successfully."`.
</ResponseField>

```bash
curl -X POST https://pamodzi-bbe9f0671866.herokuapp.com/farmers/me/change-pin \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-farmer-token>" \
  -d '{
    "current_pin": "1234",
    "new_pin": "5678"
  }'
```

## User Management Endpoints

The following endpoints provide admin-level management of all user accounts on the platform — across all roles (admin, agent, buyer, farmer). Use these to list, inspect, create, edit, and archive platform users.

---

## GET /users

Returns a list of all user accounts on the platform, across all roles. Each record reflects the base user identity.

**Authentication required:** Admin Bearer token

<ResponseField name="user_id" type="string">
  UUID of the user record.
</ResponseField>

<ResponseField name="first_name" type="string">
  User's given name.
</ResponseField>

<ResponseField name="last_name" type="string">
  User's family name.
</ResponseField>

<ResponseField name="phone_number" type="string">
  User's registered phone number.
</ResponseField>

<ResponseField name="nrc_number" type="string">
  User's Zambian National Registration Card number.
</ResponseField>

<ResponseField name="role" type="string">
  The user's role. One of `admin`, `cooperative_agent`, `wholesale_buyer`, `farmer`.
</ResponseField>

<ResponseField name="email" type="string">
  Email address. Present for admins and wholesale buyers; `null` for agents and farmers.
</ResponseField>

<ResponseField name="is_archived" type="boolean">
  Whether this user account has been archived (deactivated).
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the account was created.
</ResponseField>

```bash
curl -X GET https://pamodzi-bbe9f0671866.herokuapp.com/users \
  -H "Authorization: Bearer <your-admin-token>"
```

## POST /users

Creates a new user account. Use this endpoint to add platform users when you need direct control over the user record. For farmer onboarding, prefer [`POST /farmers/onboard`](#post-farmers-onboard) which handles cooperative association in a single call.

**Authentication required:** Admin Bearer token

<ParamField body="first_name" type="string" required>
  User's given name. 1–100 characters.
</ParamField>

<ParamField body="last_name" type="string" required>
  User's family name. 1–100 characters.
</ParamField>

<ParamField body="phone_number" type="string" required>
  User's mobile phone number. Must be unique across all user accounts.
</ParamField>

<ParamField body="nrc_number" type="string" required>
  Zambian National Registration Card number. Must be unique across all user accounts. Max 20 characters.
</ParamField>

<ParamField body="role" type="string" required>
  The role to assign. One of `admin`, `cooperative_agent`, `wholesale_buyer`, `farmer`.
</ParamField>

<ParamField body="email" type="string">
  Email address. Required for admin and wholesale buyer roles.
</ParamField>

<ResponseField name="user_id" type="string">
  UUID of the newly created user record.
</ResponseField>

<ResponseField name="role" type="string">
  The role assigned to the new user.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of account creation.
</ResponseField>

```bash
curl -X POST https://pamodzi-bbe9f0671866.herokuapp.com/users \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-admin-token>" \
  -d '{
    "first_name": "Mutale",
    "last_name": "Bwalya",
    "phone_number": "+260977000300",
    "nrc_number": "345678/90/1",
    "role": "cooperative_agent",
    "email": null
  }'
```

## POST /users/{user_id}/archive

Deactivates a user account. The user can no longer log in or perform any platform actions. The account record is retained for audit purposes.

**Authentication required:** Admin Bearer token

<ParamField path="user_id" type="string" required>
  UUID of the user account to archive.
</ParamField>

<ResponseField name="message" type="string">
  A confirmation message, e.g. `"User archived successfully."`.
</ResponseField>

<ResponseField name="user_id" type="string">
  UUID of the archived user record.
</ResponseField>

<Warning>
  Archiving takes effect immediately. The user loses all platform access at the moment this call is made.
</Warning>

```bash
curl -X POST https://pamodzi-bbe9f0671866.herokuapp.com/users/a1b2c3d4-e5f6-7890-abcd-ef1234567890/archive \
  -H "Authorization: Bearer <your-admin-token>"
```
