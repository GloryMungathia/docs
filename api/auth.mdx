The authentication endpoints handle login for all four user roles (admin, cooperative agent, wholesale buyer, and farmer), two-factor verification, admin onboarding, and logout. Most protected endpoints require a valid Bearer token obtained from these endpoints. Tokens are RS256-signed JWTs with a two-hour lifetime and must be passed in the `Authorization: Bearer <token>` header on every protected request.

<Note>
  Admins and wholesale buyers go through a mandatory two-step flow: first call the role-specific login endpoint to receive a `twofa_session_token`, then exchange it plus the OTP at `/auth/verify-2fa` to receive the final `access_token`. Cooperative agents and farmers receive an `access_token` directly on successful login.
</Note>

## POST /auth/login/admin/form

Authenticates a platform administrator using an OAuth2 password-grant form submission. On success, returns a `twofa_session_token` and dispatches a one-time password to the admin's registered contact. You then call [`POST /auth/verify-2fa`](#post-auth-verify-2fa) with that token and the OTP to receive a full `access_token`. You must submit this request as `application/x-www-form-urlencoded`, not JSON.

**Authentication required:** None

<Warning>
  This endpoint accepts `application/x-www-form-urlencoded` only — not JSON. Use `-d` form encoding in curl or set the correct `Content-Type` header in your HTTP client.
</Warning>

<ParamField body="username" type="string" required>
  The admin's registered email address. Passed as the OAuth2 `username` field.
</ParamField>

<ParamField body="password" type="string" required>
  The admin's account password.
</ParamField>

<ResponseField name="twofa_session_token" type="string">
  A short-lived session token (TTL: 5 minutes). Pass this to `/auth/verify-2fa` along with the OTP to receive a full access token.
</ResponseField>

<ResponseField name="message" type="string">
  A human-readable status message confirming that the OTP has been dispatched.
</ResponseField>

```bash
curl -X POST https://pamodzi-bbe9f0671866.herokuapp.com/auth/login/admin/form \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=admin%40example.com&password=AdminPassword123%21"
```

## POST /auth/login/buyer

Authenticates a wholesale buyer with email and password. On success, the platform generates a short-lived `twofa_session_token` (valid for 5 minutes) and dispatches a one-time password to the buyer's registered contact. You must then call [`POST /auth/verify-2fa`](#post-auth-verify-2fa) to complete login.

**Authentication required:** None

<ParamField body="email" type="string" required>
  The buyer's registered corporate email address.
</ParamField>

<ParamField body="password" type="string" required>
  The buyer's account password.
</ParamField>

<ResponseField name="twofa_session_token" type="string">
  A short-lived session token (TTL: 5 minutes). Pass this to `/auth/verify-2fa` along with the OTP to receive a full access token.
</ResponseField>

<ResponseField name="message" type="string">
  A human-readable status message confirming that the OTP has been dispatched.
</ResponseField>

```bash
curl -X POST https://pamodzi-bbe9f0671866.herokuapp.com/auth/login/buyer \
  -H "Content-Type: application/json" \
  -d '{
    "email": "buyer@example.com",
    "password": "YourPassword123!"
  }'
```

## POST /auth/login/farmer

Authenticates a farmer using their phone number and 4-digit PIN. Returns a full JWT access token directly. This endpoint is primarily called by the USSD gateway on behalf of the farmer; use it programmatically only when building custom farmer-facing tooling.

**Authentication required:** None

<ParamField body="phone_number" type="string" required>
  The farmer's registered mobile phone number (e.g. `+260977000001`).
</ParamField>

<ParamField body="pin" type="string" required>
  The farmer's 4-digit numerical PIN.
</ParamField>

<ResponseField name="access_token" type="string">
  A signed RS256 JWT. Valid for 2 hours.
</ResponseField>

<ResponseField name="token_type" type="string">
  Always `"bearer"`.
</ResponseField>

```bash
curl -X POST https://pamodzi-bbe9f0671866.herokuapp.com/auth/login/farmer \
  -H "Content-Type: application/json" \
  -d '{
    "phone_number": "+260977000001",
    "pin": "1234"
  }'
```

## POST /auth/login/agent

Authenticates a cooperative agent using their `staff_id` and password. Returns a full JWT access token directly — no 2FA step is required for agents.

**Authentication required:** None

<ParamField body="staff_id" type="string" required>
  The agent's platform-assigned staff identifier (max 20 characters).
</ParamField>

<ParamField body="password" type="string" required>
  The agent's account password.
</ParamField>

<ResponseField name="access_token" type="string">
  A signed RS256 JWT. Valid for 2 hours. Pass this as `Authorization: Bearer <token>` on all protected requests.
</ResponseField>

<ResponseField name="token_type" type="string">
  Always `"bearer"`.
</ResponseField>

```bash
curl -X POST https://pamodzi-bbe9f0671866.herokuapp.com/auth/login/agent \
  -H "Content-Type: application/json" \
  -d '{
    "staff_id": "AGT-001",
    "password": "AgentPassword123!"
  }'
```

## POST /auth/verify-2fa

Exchanges a `twofa_session_token` and the user-supplied OTP for a full JWT access token. This is the second step of the two-factor authentication flow for admins and wholesale buyers. The session token is destroyed server-side on successful verification.

**Authentication required:** None

<ParamField body="twofa_session_token" type="string" required>
  The temporary session token returned by `/auth/login/buyer` or `/auth/login/admin/form`. Expires after 5 minutes.
</ParamField>

<ParamField body="otp_code" type="string" required>
  The one-time password delivered to the user's registered phone or email address.
</ParamField>

<ResponseField name="access_token" type="string">
  A signed RS256 JWT. Valid for 2 hours. Use as `Authorization: Bearer <token>` on all subsequent protected requests.
</ResponseField>

<ResponseField name="token_type" type="string">
  Always `"bearer"`.
</ResponseField>

```bash
curl -X POST https://pamodzi-bbe9f0671866.herokuapp.com/auth/verify-2fa \
  -H "Content-Type: application/json" \
  -d '{
    "twofa_session_token": "your-twofa-session-token",
    "otp_code": "847392"
  }'
```

## POST /auth/forgot-password/email

Initiates the password reset flow for a user account. If the provided email matches a registered account, the platform sends a reset link to that address. The response is always a generic success message regardless of whether the email exists — this prevents account enumeration.

**Authentication required:** None

<ParamField body="email" type="string" required>
  The email address associated with the account you want to reset.
</ParamField>

<ResponseField name="message" type="string">
  A generic success message such as `"If that email is registered, a reset link has been sent."` The response is identical whether or not the email exists.
</ResponseField>

```bash
curl -X POST https://pamodzi-bbe9f0671866.herokuapp.com/auth/forgot-password/email \
  -H "Content-Type: application/json" \
  -d '{
    "email": "buyer@example.com"
  }'
```

## POST /auth/admin/onboard

Creates a new administrator account. You must already be authenticated as an admin to call this endpoint.

**Authentication required:** Admin Bearer token

<Note>
  The very first admin account is provisioned automatically at system startup — there is no self-service path to create it. Use this endpoint only to onboard additional admins once you are already logged in.
</Note>

<ParamField body="first_name" type="string" required>
  The new admin's given name. 1–100 characters.
</ParamField>

<ParamField body="last_name" type="string" required>
  The new admin's family name. 1–100 characters.
</ParamField>

<ParamField body="email" type="string" required>
  A valid email address for the new admin. Used as their login username.
</ParamField>

<ParamField body="phone_number" type="string" required>
  The new admin's phone number. Used for OTP delivery during login.
</ParamField>

<ParamField body="nrc_number" type="string" required>
  The new admin's Zambian National Registration Card number. Max 20 characters. Required on all user records across all roles.
</ParamField>

<ResponseField name="message" type="string">
  A confirmation message such as `"Admin account created successfully."`.
</ResponseField>

<ResponseField name="admin_id" type="string">
  The UUID of the newly created admin record.
</ResponseField>

```bash
curl -X POST https://pamodzi-bbe9f0671866.herokuapp.com/auth/admin/onboard \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-admin-token>" \
  -d '{
    "first_name": "Chanda",
    "last_name": "Mwale",
    "email": "chanda.mwale@pamodzi.co.zm",
    "phone_number": "+260977000002",
    "nrc_number": "123456/78/1"
  }'
```

## POST /auth/logout

Ends the current session by clearing the session cookie. Returns a success message.

**Authentication required:** None

<ResponseField name="message" type="string">
  A confirmation message such as `"Logged out successfully."`.
</ResponseField>

<Warning>
  This endpoint clears the session cookie. The JWT Bearer token remains valid until its 2-hour expiry window passes. Discard the token on the client side immediately after calling logout.
</Warning>

```bash
curl -X POST https://pamodzi-bbe9f0671866.herokuapp.com/auth/logout \
  -H "Authorization: Bearer <your-token>"
```
